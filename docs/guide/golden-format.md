# Golden file format

A golden is the expected output of a run: the screens a test script snapshots, in order, with the volatile parts
declared. This page is the user's reference for the file. The normative grammar, every error rule and the reasoning are
in section 6 of the [snapshot and golden contract](../design/snapshot-and-golden-contract.md) (the grammar is 6.1 to
6.3, the regex dialect 6.7, what a reader must reject and accept 6.13); where this page and that one disagree, the
contract wins. How to run a test is in [testing TUIs](testing-tuis.md) and the
[CLI reference](cli-reference.md#testing-with-goldens---expect).

## A golden at a glance

```
vtee-golden 1
schema 1
semantics 1
ignore title

[masks]
# The clock at the right end of the last row, on every screen.
mask row=3 cols=15-19 text=/\d\d:\d\d/

[screen 1]
size 20x4
cursor row=0 col=0 shape=block hidden=false
modes
alt_screen false
title null
name "startup"

[text]
0|welcome
1|
2|
3|               12:01

[assert]
assert row=0 text="welcome" !bold
```

- The lines before the first `[screen N]` are the **file header**: `vtee-golden 1` (the grammar number, always first),
  `schema` and `semantics` (the snapshot versions the golden was recorded under) and `ignore` lines for the whole file.
- A golden always holds one or more `[screen N]` blocks, numbered from 1 in order. A one-screen golden is a composite of
  one.
- Each screen has a header (`size`, `cursor`, `modes`, `alt_screen`, `title`, and optionally `wrapped`, `name` and its
  own `ignore`), then `[text]`, and optionally `[attrs]`, `[masks]` and `[assert]`.
- A `[masks]` section before the first screen is shared by every screen.
- Lines starting with `#` are comments, allowed in headers, `[masks]` and `[assert]`, not in `[text]` or `[attrs]`.
- Rows and columns are counted from 0. UTF-8, LF line endings (CRLF is read, never written).

## `[text]` and `[attrs]`

`[text]` has one line per row: the row number, `|`, then one token per cell. Most cells are the character itself. A
backslash is `\\`; invisible, combining, private-use and non-ASCII-space characters are `\u{H}` (hex code point); the
second half of a wide character is `\.`; an extra scalar on the same cell (a combining mark) is `\+{H}`. Trailing blank
cells are left out, so a row never ends in a space.

`[attrs]` lists only cells that are not plain, as runs: `ROW: COLS TOKENS`, for example `1: 0-7 fg=idx:1 bold`.
Colours are `default`, `idx:N` or `rgb:#rrggbb`. The flags are `bold dim italic reverse strike conceal`, plus
`underline=STYLE`, `ulcolor=C` and `link="URI"`.

Both sections are regenerated by `--update`, so do not edit them by hand and do not put comments in them.

## `ignore`

`ignore` tells the comparison to skip a part, in the file header (all screens) or a screen header (that screen):

| Line | Skips |
| --- | --- |
| `ignore title` | the window title |
| `ignore alt_screen`, `ignore wrapped` | those fields |
| `ignore cursor` | the cursor position, shape and visibility (or `cursor.position`, `cursor.shape`, `cursor.hidden`) |
| `ignore modes TOKEN...` | the listed terminal modes, on both sides |
| `ignore attrs NAME...` | the listed attributes (`fg`, `bg`, `bold`, ...) in every cell comparison; the cell text is still compared |

A screen skips the union of both lists; nothing cancels a file-wide `ignore`.

## Masks

A mask relaxes the comparison for a region. Everything outside every mask is compared in full.

```
mask row=3 cols=15-19 text=/\d\d:\d\d/
mask rows=5-8 attrs=ignore
mask find=/load average: [\d., ]+/ text=ignore
```

- The region is `row=N`, `rows=N-M`, optionally with `cols=N-M`, or `find=/RE/` (every match on the optionally
  restricted rows and columns).
- `text=ignore` skips the text; `text=/RE/` skips the stored text but requires the actual text to match the whole
  pattern; `attrs=ignore` skips the attributes. A mask needs at least one of them.
- A shared mask applies to every screen; a mask inside a screen applies to it alone.
- A `find=` mask that matches nothing is **stale** and fails the check (a shared one is stale only if it matches in no
  screen). A mask that cannot find its target means the program changed, and you should notice.

## Assertions

`[assert]` checks the actual screen for what matters, whatever `[text]` says:

```
assert row=1 text="hello" !bold
assert find=/goblin/ fg=idx:1 bold
assert rows=0-2 cols=0-9 underline=none
```

`text="..."` is an exact JSON string for a single row. `text=/RE/` matches the whole span. Attribute constraints must
hold for every cell of the span, and with `find=` every match must satisfy them. An assertion whose region finds nothing
fails. There is no shared `[assert]`.

## Regular expressions

Patterns in `text=/RE/` and `find=/RE/` use a small dialect that is the same in every language: literals, `.`, classes,
groups, `|`, the quantifiers `* + ? {m,n}` (and lazy forms) and the anchors `^ $`. `\d \w \s` are ASCII. A literal `/`
is `\/`. Lookaround, back-references, `\b`, inline flags, named groups and `\p` are rejected when the golden is read.

## Recording and updating

```
vtee --script flow.ndjson --expect flow.golden --update --portable -- APP     # create or regenerate
vtee --script flow.ndjson --expect flow.golden -- APP                         # check
```

`--update` writes only if the run succeeded. It keeps your `ignore` lines, masks, assertions and comments, regenerates
`[text]`, `[attrs]` and the screen headers, and prints what changed. `--update=restamp` only advances the `semantics`
number, and only if a run under this build still matches everything the golden checks. `--update=migrate` is not
available in this release.

Add `*.golden text eol=lf` to `.gitattributes`.

## Versions and refusals

A golden records `schema` and `semantics`. A build whose numbers differ **refuses** the golden instead of guessing: the
check exits **2**, compares nothing, and the report names both numbers and the command to run next (`--update=restamp`
if nothing you check changed, otherwise a plain `--update` and a review of the diff). The decision is made from the file
header before the program is started. A golden with a newer grammar number is refused the same way.

| Exit | Meaning |
| --- | --- |
| 0 | pass, or an update that succeeded |
| 1 | the output differs (or a `wait_for` timed out, or an update refused to write) |
| 2 | refused: version mismatch, nothing compared |
| 64 | usage error |
| 65 | the golden, script or saved output is malformed |
| 66 | a named file does not exist |

The full table is in the [CLI reference](cli-reference.md#testing-with-goldens---expect). What counts as a change to
`schema` or `semantics` is in [versioning](versioning.md) and the [semantics changelog](snapshot-semantics.md).

## In CI

`--update` is refused with exit 64 when `CI` is set and non-empty, unless `VTEE_ALLOW_UPDATE=1` is also set, so a
pipeline cannot rewrite its own expectations. A check is never guarded.

## One golden on Linux and Windows

`--portable`, given when the golden is created, adds `ignore` lines for what ConPTY changes: the window title, the
terminal modes it hides and the underline colour. A portable golden passes on both platforms provided the program's
output is the same there. This repository checks a few of its own on both CI platforms (`tests/goldens/`).
